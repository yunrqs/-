# 走神/专注融合：设计、接口与验证

本文说明情绪识别与眨眼检测如何接入专注识别，取代此前"仅数据跑通、无实际应用能力"的状态。

- 代码位置：`backend/src/mind_wandering/fusion/`
- 测试：`backend/src/mind_wandering/tests/test_fusion.py`（15 项）
- 仿真：`python -m backend.src.mind_wandering.fusion.demo_simulate --verbose`
- 论文依据：IEICE Trans. Inf. & Syst. Vol.E109-D No.7 (2026), Mamun et al.

---

## 1. 为什么此前融不进去

不是代码缺，是三个信号在时间上对不上：

| 信号 | 原始频率 | 性质 |
|---|---|---|
| EAR / 眨眼 | 每帧 | 连续值 + **稀疏事件** |
| 情绪概率 | 每帧（检出人脸时） | 7 维单纯形 |
| 人脸/姿态 | 每帧 | 布尔 + 角度 |

直接逐帧拼接有两个致命问题：

1. **眨眼不能按帧平均**。`blink_detected` 只在眨眼触发帧为 True，取均值恒接近 0。
2. **5 秒窗口估不准眨眼率**。眨眼约 0.2–0.3 Hz，5 秒窗内仅 1–2 次；折算成次/分会在 12 与 24 之间成倍跳变，判决每秒反复横跳。**这是最初实现中最主要的技术障碍**，实测日志里同一场景在 0% 与 160% 基线间来回切换。

## 2. 架构：三层

```
帧级输入 ──► 时序对齐 ──► 决策层融合 ──► 状态输出
(FrameSample)  (双时间尺度)   (规则打分)     (AttentionVerdict)
```

- `fusion_types.py` — 数据契约
- `window.py` — 窗口聚合 + `BlinkRateEstimator`
- `rules.py` — 三态打分
- `engine.py` — 校准、持续性约束、降级
- `config.py` — 全部阈值与权重集中管理（遵循项目既有约定）

## 3. 时序对齐：双时间尺度

| 特征 | 时间常数 | 理由 |
|---|---|---|
| 情绪（valence、熵、切换率） | 5 秒窗口，1 秒步长 | 高频信号，可快速响应 |
| 眨眼率 | 30 秒滑动窗，事件间隔法 | 低频事件，短窗统计上不可用 |

眨眼率估计采用 `(n-1) / 事件跨度`，而非 `n / 窗口时长`，对单次事件误差不敏感。

**四条必须处理的边界**（均已实现并由测试覆盖）：

1. 以**时间戳**为主键，不以帧序号——前端上传帧率随网络抖动，按帧切窗会让 5 秒窗漂移成 10 秒以上。
2. 眨眼按**事件计数**，不按帧比例折算。
3. 相邻帧间隔超过 `max_frame_gap_sec(1.5s)` 视为断流，**丢弃旧窗口重建**，避免把两段无关行为混为一谈。
4. 情绪只统计**检出人脸的帧**；人脸丢失时若补 neutral=1，会系统性压低负性情绪占比。

## 4. 融合判据

**决策层融合而非特征层拼接**：当前没有"带探针标签的视频"，特征层融合需要训练标签；决策层规则可零训练上线，并天然产出伪标签，为后续有监督训练积累数据。

三态**各自独立打分，取最高者**（不是阈值分类）：

```
focused        = 0.40·近基线 + 0.40·emo(中性/负性)      + 0.20·stab(低熵)
deliberate_mw  = 0.40·低于基线 + 0.40·emo(0.5(正性+中性)/负性) + 0.20·stab(低熵)
spontaneous_mw = 0.40·高于基线 + 0.40·emo(负性/中性)      + 0.20·stab(高熵)
```

| 状态 | 主要依据 | 论文出处 |
|---|---|---|
| 专注 focused | 眨眼率贴合个体基线、中性主导、表情稳定 | 2.5、4 |
| 有意走神 deliberate_mw | 眨眼率**低于**基线、表情受控（熵低） | 4：有意走神表情更受控 |
| 无意走神 spontaneous_mw | 眨眼率**高于**基线、负性情绪高、情绪离散度大 | 4：负性情绪是区分两类走神的关键，无意走神变异更大 |

**两处对称化（消除结构性偏置）**。打分后取最高者，因此任何只出现在部分状态里的项都会造成偏置：

- 情绪项不许用绝对占比。真实 FER 输出里中性常占 0.50–0.95、负性常占 0.05–0.20，直接相减会让"专注"凭中性占比先天领先 0.35，超过眨眼项上限 0.30，`spontaneous_mw` 分支事实上不可达（曾实测：眨眼率飙到基线 2 倍仍判专注）。现一律取对数几率 `emo(X)=0.5+0.5·tanh(log(X分子/X分母)/2)`。因 `log(中性/负性) = -log(负性/中性)`，**专注与无意走神的情绪项之和恒为 1**。
- 熵项同理：`stab(低熵)=squash(H_mid-H)` 与 `stab(高熵)=squash(H-H_mid)` 互为镜像。

**人脸覆盖率不参与打分**。它是三态共模项，对 argmax 恒无贡献（实测 face 从 1.00 降到 0.65，三态分数完全不变），原来占 0.15 权重只是名义上的。现在只用于置信度折扣。

**置信度**取 Hill 函数 `margin/(margin+tau)`：渐近趋 1、永不饱和，语义是**判定强度而非概率**。再按人脸覆盖、眨眼率可用性、是否校准三项折损。**专注态在没有走神阳性证据时封顶 0.60**——三个走神分支都无阳性信号时，"专注"只是排除法结论，不能与有明确证据的判定同等确信；否则会出现"信息越少越确信"。

**可判性门槛**：top1 与 top2 间隔小于 0.02 时输出 `unknown`，不用浮点噪声决定状态。典型触发情形是"眨眼明显偏离、但表情完全中性"——此时 focused 与 deliberate 的各项分量几乎并列。

**实测边界**（对 `decide()` 参数扫描，不是准确率）：

| 情形 | 结果 |
|---|---|
| 眨眼率偏离、表情全中性 | `unknown`（信息不足，不再给虚假高置信结论） |
| 眨眼率 1.5× 基线，负性情绪 0.15 | 判 `spontaneous_mw`（修复前需 0.20，门槛降 25%） |
| 无走神阳性证据 | `focused`，置信度封顶 0.60 |
| 输入 ±10% 扰动 | 判决翻转率约 13% |

权重与阈值**全部为 `[先验]`，未经实测数据校准**。这是当前主要的不确定来源。

**必须说明的限定**：论文报告的 RF 99% 是"探针标签训练的模型在随机划分下的准确率"，**规则法本身在论文中从未被单独评估**。本章的打分规则是可解释的启发式，不构成任何精度承诺。


**个体基线校准**：会话开始 30 秒内以实测眨眼率替代经验值。论文 3.6 节 Fig.7 明确指出被试间差异显著，固定阈值必然失效。校准完成前一律输出 `unknown`，不给三态标签。

**持续性约束**：连续 2 个窗口同向才切换状态（对应论文 2.6 节的 state-persistence），抑制单窗口抖动。

## 5. 应用接口

### 5.1 HTTP 接口（无破坏性变更）

`POST /api/analyze` 在原有返回体上**新增两个字段**，既有字段语义不变，前端不改也不会报错：

```jsonc
{
  "ear": 0.28, "emotion": "neutral", "blink_rate_per_min": 14.2,
  // ... 原有字段保持不变 ...
  "attention": {
    "state": "focused",              // focused | deliberate_mw | spontaneous_mw | unknown
    "raw_state": "focused",          // 持续性约束生效前的瞬时判定
    "confidence": 0.60,              // 判定强度（Hill 函数），不是概率
    "scores": { "focused": 0.77, "deliberate_mw": 0.57, "spontaneous_mw": 0.28 },
    "signals": { "blink_ratio": 1.02, "score_margin": 0.20, "negative_valence": 0.10 },
    "reason": "眨眼率贴合个体基线；中性表情主导",
    "calibrated": true
  },
  "attention_calibration": { "calibrated": false, "progress": 0.4, "remaining_sec": 18.0 }
}
```

`confidence` 语义：`min(1, 分差 / 0.32) × 人脸覆盖率`，未校准时再乘 0.6。它表达"判定有多确定"，**不能当概率用于阈值决策**。

### 5.2 Python 接口

```python
from backend.src.mind_wandering.fusion import AttentionEngine, FrameSample

engine = AttentionEngine()
verdict = engine.feed(FrameSample(t=t, face=True, ear=0.28, blink=False,
                                  emotion="neutral", probs={...}))
current = verdict or engine.latest     # 每帧都要有值，窗口间隔期内沿用上次
```

### 5.3 前端接入

`web-react` 已在仪表盘新增「注意力状态」面板（`src/features/monitoring/components/AttentionPanel.tsx`），只读消费上述两个字段，不新增接口、不改后端。

- **三态展示**：`attention.state` 映射为「专注 / 有意走神 / 无意走神」；`unknown` 分两种来源——未校准显示校准进度与「保持自然状态」引导，已校准则显示「证据不足」。校准期间不出现任何三态标签。
- **证据不足不指认成因**：后端产出 `unknown` 有三种成因（人脸覆盖不足、未校准、分数间隔过小），其中人脸覆盖不足在已校准时同样会出现。因此该形态直接展示后端 `reason` 原文，由后端说明到底是「请调整坐姿」还是「状态本身模糊」；前端固定写死成「分数过于接近」会把前者误报成后者，指引就错了。`reason` 缺失时才使用不指向具体成因的兜底文案。
- **等级换算**：`confidence` 不按百分比呈现，而是折成四档——`≥0.75` 高、`≥0.45` 中、`>0` 低，否则证据不足。面板固定标注「等级只表示本次判定有多确定，不代表准确率」。
- **降级路径**：`attention` 为 `null`（首个窗口产出前）或 `attention_calibration` 整键缺失（旧版后端）时整块隐藏，仪表盘其余面板不受影响。

映射逻辑抽在 `src/features/monitoring/core/attention-view.mjs`，由 `tests/unit/attention-view.test.mjs` 覆盖，组件只负责渲染。

## 6. 已知局限（汇报时必须说明）

1. **状态切换滞后**：眨眼率用 30 秒窗估计，状态变化后约需 10–20 秒才反映。仿真中 deliberate 段在第 21 秒才完成切换。认知状态本身是分钟级构念，此滞后可视作平滑代价；若需更快响应，减小 `blink_rate_window_sec`，代价是抖动加剧。
2. **三项权重与各容差均为先验值**。没有带标签的视频，无法定量评估准确率——**当前只能证明"可用、可解释、可复现"，不能宣称"准确率 x%"**。
3. **眨眼率单独不足以判定走神**。眨眼明显偏离基线、但表情完全中性时，系统输出 `unknown` 而非任何一类走神。这是刻意的：该情形下"眨眼偏多的专注者"与"走神者"在现有特征上不可分，强行判定就是猜测。代价是长时间中性表情 + 眨眼偏高的用户会看到较多 `unknown`。
4. **`focused` 的置信度上限被刻意压到 0.60**。规则法只能"没有发现走神证据"，不能"确证专注"，因此不应给出高置信度。若前端把 confidence 当"准确率"展示会误读。
5. **规则版不是最终形态**：它的定位是立即上线 + 产出伪标签。伪标签积累到 300 条以上后，应转为有监督模型（复用 `training/train.py` 的 GroupKFold 流程）。
6. **情绪标签与概率不同步**：`EmotionRecognizer.predict` 返回 10 帧众数平滑后的标签，但概率是当前帧的。融合层里熵用概率（即时分布）、切换率用平滑标签（稳态），二者互补，但会在状态切换瞬间短暂失配。
7. **对负性情绪的敏感度提高后，稳定性略降**。改用对数几率使低概率类的相对变化被放大，±10% 输入扰动下的判决翻转率从约 10% 升至约 13%。这是换取对称性的代价，由持续性约束兜底。

## 7. 验证

```bash

PYTHONPATH=. backend/.venv/Scripts/python.exe -m unittest backend.src.mind_wandering.tests.test_fusion -v

# 仿真：三档合成信号，检验状态分离
PYTHONPATH=. backend/.venv/Scripts/python.exe -m backend.src.mind_wandering.fusion.demo_simulate --verbose
```

仿真输出（默认 30 秒校准 + 三段各 30 秒）：

```
个体基线眨眼率: 15.0 次/分
判决窗口数: 118
状态分布: {'unknown': 31, 'focused': 39, 'deliberate_mw': 22, 'spontaneous_mw': 26}
```

`unknown` 31 个窗口：25 个来自启动与校准期（未校准不判定），6 个来自状态交界处分数过于接近（可判性门槛）。状态序列为 focused → deliberate_mw → spontaneous_mw，迁移正确。
